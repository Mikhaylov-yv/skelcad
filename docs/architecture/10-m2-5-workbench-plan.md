## Сквозной сценарий конструктора

Изделие проходит четыре этапа; у проекта всегда ровно один следующий шаг, он написан словами и стоит в
одном и том же месте экрана и в дереве у названия проекта.

| Этап | Кто делает | Что видно | Следующий шаг |
|---|---|---|---|
| 1. Задание | конструктор: текст (назначение, нагрузки, крепление) + набросок или фото | текст и набросок | «Поручить агенту компоновку» |
| 2. Компоновка | агент: требования, скелет, обстановка → компоновочный эскиз | эскиз во весь экран, 3 числа (базы, интерфейсы, обстановка), допущения свёрнуты | «Согласовать компоновку» (янтарное — решение за конструктором); «Поправить на эскизе», «Обвести замечание» |
| 3. Конструкция | агент: генератор, детали, варианты, проверки | 3D или эскиз с размерами, по варианту три числа: масса, K min, замечания | «Сравнить и выбрать» → «Выбрать» на варианте; при ошибках «Поручить агенту устранить» |
| 4. Комплект | агент: сборка с экспортом | файлы: STEP, эскизы, спецификация, отчёт | «Выдать комплект» → «Скачать» |

Правила:

- Состояние этапа выводится из проекта, а не хранится отдельно: задание есть ↔ `requirements`/задача;
  компоновка: `layout.yaml` (none / waiting / approved / changed); конструкция: варианты собраны, ошибки,
  выбранный вариант; комплект: экспорт по выбранному варианту.
- Цвет только у решения: янтарное — ждёт конструктора, синее — ход у агента или следующий шаг, зелёная точка —
  готово. Одна залитая кнопка на экран — следующий шаг.
- Ход агента — фразами и картинками, на которые он смотрел (D30); отчёт тремя строками; сырое — свёрнуто.
- Папки: дерево слева, создать и удалить — кнопками над деревом и правой кнопкой; удаление возвращается
  («Вернуть» в сообщении, Ctrl+Z).
- Задачи агенту по этапам стандартные («компоновка по заданию», «детали по согласованной компоновке»,
  «комплект»), свой текст — по желанию; после «Согласовать» следующий шаг предлагается сразу.

- справа — единое место общения с агентом (разговор), а не панель «Сейчас»;
- центр — рабочая зона, разбирать отдельно и позже.

По этим замечаниям собран макет **05 «Узлы и разговор»** (`v05-nodes.html`) на изделии из нескольких узлов —
насосный агрегат К 100-65-200 на раме: рама, насос из каталога, опоры насоса, трубопровод с кронштейном и опорой
(узел — проект внутри проекта, D24, D25):

| Область | Что там |
|---|---|
| Шапка | «☰ Проекты» (папки и проекты выезжают панелью, это второстепенный путь), крошки «папка › изделие › узел», этапы выбранного узла; у сводного узла этапы «Задание · Общая компоновка · Узлы · Сводный комплект» |
| Слева | состав изделия: узлы деревом, у каждого точка состояния и строка «что дальше»; «+ Узел», правая кнопка; покупной узел помечен «каталог» |
| Центр | картинка узла: общая компоновка с зонами узлов, компоновка узла, 3D или эскиз варианта; у сводного узла сводка вверх (узлов, готово, масса узлов, K min) и полоса узлов; у листового — полоса вариантов с числами и «Выбрать» |
| Справа | разговор по узлу (переключатель «узел / всё изделие»): закреплённая карточка следующего шага; сообщения — ваши задачи и решения, отчёты агента в три строки с картинкой и кнопками решения («Согласовать», «Выбрать B», «Выдать комплект»), вопросы агента с вариантами ответа, служебные записи (коммиты, согласования); ход работы агента как живое сообщение; поле «Написать агенту» — задание нового узла тоже пишется здесь |

Правила разговора, чтобы он не стал стеной текста: сообщение агента не длиннее трёх строк плюс картинка; решение
всегда кнопкой внутри сообщения; вопрос агента — карточка с вариантами; сырое свёрнуто; лента привязана к узлу,
«всё изделие» — по переключателю.

Прогон 05 — свой набор из 10 сценариев (узлы и разговор): 10/10, 20 действий, ошибок JS нет. Предложение
(`picks.json`): за основу — 05. Открытые вопросы: что показывать в центре у сводного узла (общая компоновка с
зонами или сборка 3D), нужен ли фильтр разговора по узлу по умолчанию, автозапуск следующего шага агента после
согласования.

## Решения по открытым вопросам (2026-10-21, «реши пока сам»)

Принятые допущения выписаны явно, чтобы их можно было оспорить:

1. **После «Согласовать компоновку» агент сам берётся за детали.** Ход у агента, решения конструктора не нужно;
   задача «Сделай детали по согласованной компоновке» ставится сервером от имени конструктора, провайдер — по
   умолчанию; в разговоре это служебная строка «Агент продолжает сам: …», остановить можно как любую задачу.
   Комплект после выбора варианта — по кнопке: экспорт долгий, а конструктор после выбора часто ещё правит.
   Задание нового узла — первое сообщение агенту, оно же запускает компоновку. Допущение: автопродолжение без
   настройки; выключатель на проект — если попросят.
2. **Разговор по умолчанию:** у узла — только этот узел, у изделия — всё изделие с подписью узла у сообщения;
   переключатель «узел / всё изделие» остаётся. Допущение: контекст следует за картинкой; на корне нужен обзор.
3. **Центр сводного узла — общая компоновка с зонами узлов**, сводка вверх (узлов, готово, масса узлов, K min) и
   полоса узлов. 3D-сборка из выбранных вариантов узлов — вкладка появится с деревом компоновок (M3), пока
   выключена с подсказкой. Допущение: на уровне изделия решают зоны и интерфейсы, сборка — производная.

## Доработки после первой живой задачи (2026-10-21)

Замечания конструктора после задачи на `skelcad.br`: «в проекте должна быть удобная зона для файлов пользователя:
эскизы, примеры и т. д.»; «в чате часто странно переносится текст, его нельзя сделать уже или шире». Сделано
(ревью `docs/ui/reviews/23-files-chat.md`, приёмка 14/14; коммит `8ec74ea`, деплой run 648, на `skelcad.br`
разговор по болту уже показывает ответы без отчёта словами):

| Что | Как |
|---|---|
| Зона файлов проекта | вкладка «Файлы» справа и галерея на «Задании» (`ui/wb/FilesPane.tsx`): перетаскивание, «Добавить файлы» с заметкой, вставка из буфера и перетаскивание в поле сообщения, миниатюры (`GET …/attachments/<файл>/thumb`, кэш в `out/<проект>/_attachments/`), «В сообщение», удаление с «Вернуть» (откат коммита). Заметка — из сообщения коммита `вложение <файл>: <заметка>` |
| Переносы в разговоре | `thread.brief` — краткий ответ одной строкой без разметки (320 знаков по слову); `pre-wrap` только у сообщений конструктора, `overflow-wrap: anywhere`; шапка этапов переименована в `.stepper` — её `.steps` перекрывал список шагов агента (шаги живой задачи вставали в строку) |

| Ответы без отчёта и шаги | `thread.failure_text`: таймаут провайдера, лимит шагов, остановка — словами с подсказкой; в ответе агента «Шаги агента (N)» раскрывают `Progress` законченной задачи |

Наблюдения по живой задаче (болт М16, модель `deepseek-v4-flash`, провайдер по умолчанию): (1) ответ на вопрос
конструктора «почему такая компоновка, нужен разрез по оси с размерами и гайкой» упал через 16 шагов с
`ReadTimeout: timed out` — таймаут HTTP-клиента провайдера; (2) задача «детали» упёрлась в лимит 60 шагов без
единой сборки: агент читал генераторы чужих проектов по угаданным именам (`generators/pipe_support.py`), звал
`model_query` без обязательных параметров и `files_write` со строкой вместо словаря, то есть не справлялся с
аргументами инструментов. Что предлагается дальше (не сделано): пример-генератор тела вращения (болт, вал) в
шаблонах, чтобы агент копировал, а не выдумывал; подсказки в ошибках инструментов с примером правильного вызова;
таймаут и повтор запроса к провайдеру; модель по умолчанию сильнее в вызове инструментов (проверить на той же
задаче); лимит шагов с предупреждением за 10 шагов до конца, чтобы агент успел отчитаться.

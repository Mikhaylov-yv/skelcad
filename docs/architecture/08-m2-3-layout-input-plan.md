## Цель и критерий готовности

Сегодня компоновку задаёт агент текстом в `project.yaml`, конструктор согласовывает её на эскизе и ставит пометки.
Нет входа «от руки» и нет правки компоновки без YAML. Три канала в один `project.yaml` (D22):

1. **Набросок.** Фото, скан, рисунок с планшета или экспорт из доски прикладывается к задаче агенту и хранится в
   репозитории проекта как исходный документ; агент видит картинку, переводит её в скелет и обстановку,
   компоновочный эскиз показывает, как он понял; конструктор поправляет.
2. **Правка на эскизе.** Выбранную сущность компоновки (короб, плоскость, цилиндр, зону, базу, интерфейс) можно
   сдвинуть и растянуть ручками прямо на эскизе, а размер — ввести числом; точные значения — в панели полей.
   Каждое действие — коммит конструктора; хеш согласования меняется, как при любой правке скелета.
3. **Штрих поверх эскиза.** Пометка замечания может быть не точкой, а росчерком (обвести место, показать стрелку);
   росчерки видны всем в рабочем месте и агенту в `render(layout=true)`.

Критерий: **(а) конструктор прикладывает набросок к задаче, агент получает его как изображение, описывает скелет
и обстановку, компоновка появляется на экране и совпадает с наброском по составу и взаимному расположению;
(б) конструктор двигает короб обстановки и зону на эскизе, вводит число у размера — в `project.yaml` появляется
коммит от его имени, эскиз и состояние согласования обновляются, агент видит изменение в `diff`; (в) росчерк
конструктора с текстом виден на эскизе у всех и в PNG у агента; (г) опыт с доской: компоновка выгружается в
Excalidraw, правка возвращается агенту файлом и применяется к модели.**

## Принципы

- YAML остаётся единственным источником истины: ручки, числа и росчерки — это правки `project.yaml` и
  `review.yaml`, а не параллельная модель (D22). Солвера ограничений нет: сущности заданы числами.
- Правка текстом, не перезаписью: как `params.py` для параметров — найденное поле меняется на месте, комментарии
  и порядок сохраняются.
- Привязки понятные: сетка 5 мм для ручек, точные значения в полях; никакой «магии» привязок к соседям в этом этапе.
- Вложения в репозитории проекта (`attachments/`): png / jpg / webp / svg / pdf (первой страницей) / excalidraw,
  загрузка до 16 МБ, растр уменьшается до 3000 px по длинной стороне и поворачивается по EXIF (набросок — не
  архивный документ; конструктор, 2026-10-21: «можно и побольше изображение»); коммит от имени конструктора;
  агент получает их инструментом как изображение.
- Интерфейс по чеклисту `docs/ui/checklist.md`, ревью `docs/ui/reviews/15-…`.

## Ответы конструктора (2026-10-21)

- Вложения в git проекта — да, изображение можно и больше 2 МБ → 16 МБ при загрузке, 3000 px после.
- Правка на эскизе — пока только компоновка (скелет и обстановка); детали меняются параметрами варианта,
  «управляющие размеры» деталей — к M2.4 вместе с видами.
- Очерёдность: пока задача у агента выполняется, режим «Править» закрыт; конфликт после задачи разрешает git
  (это и есть отложенное D6).
- Доска: не понятно, зачем она нужна, — опыт сведён к вводу набросков через вложения (шаг 5), выгрузка компоновки
  в доску отложена до результата шага 2.
- Планшет: росчерки пером для пометок (шаг 3); набросок «с нуля» — файл или доска.
- Что агенту можно делать по наброску: создать проект, если его нет, описать скелет, обстановку и нагрузки,
  угаданное записать в `assumptions`, остановиться на согласовании компоновки; детали — после согласования.
- Виды: фиксированный набор (front / top / side / iso / layout) нужен, но число вспомогательных видов зависит от
  изделия — от одного до множества местных видов и вырывов для мелких особенностей → в M2.3 вид = строка из
  фиксированного набора; именованные вспомогательные виды (местный вид, выносной элемент, разрез, вырыв) — M2.4.

## Проверка модели

Встроенный агент на cloud (`compose/env.home`: OpenRouter, `anthropic/claude-sonnet-4.5`) изображения принимает,
но секрет `SKELCAD_LLM_API_KEY` в Gitea пуст (в `set-gitea-secrets.sh` его нет) — задачи из рабочего места на
cloud падают «провайдер модели ответил 401» ещё с M2. Проверка «модель видит набросок» живьём — после того, как
конструктор добавит ключ; путь через Claude Code (MCP Image) проверяется инструментом `attachment` напрямую.

# M0. Обобщение пилота — план работ

Цель этапа (см. `01-vision-and-architecture.md`, раздел 6): ядро модели выделено из пилота
`Kronshteqin`, схема модели описана, ГОСТ-таблицы и правила вынесены в пакет `std-gost`,
есть CLI `build / check / compare` и тесты.

Критерий готовности: второй класс изделий (не кронштейн) строится теми же модулями;
ядро собирается и работает без единого пакета стандарта.

## Устройство репозитория

```
pyproject.toml                 uv-workspace; пакет skelcad (ядро + CLI)
src/skelcad/
  core/                        проектная модель (pydantic v2), замечания, расчётные позиции,
                               загрузка проекта из YAML, JSON Schema
  context/                     реестр пакетов стандартов, доступ к таблицам (каталогам)
  geom/                        модель -> тела build123d; экспорт STEP/glTF/STL/манифест; SVG-виды
  rules/                       контракт плагинов (rule / check / calc / generator / metrics),
                               встроенные геометрические проверки
  pipeline.py                  build: модель -> геометрия -> замечания -> метрики -> артефакты
  compare.py                   страница сравнения вариантов
  cli.py                       skelcad build | check | compare | schema | check-env
packages/std-gost/             пакет стандарта: таблицы ГОСТ/СП (YAML) + правила над ними
examples/bracket/              пилот «сварной кронштейн» как проект SkelCAD:
                               project.yaml, variants/*.yaml, generators/, plugins/
tests/                         ядро без стандартов; регрессия кронштейна против пилота
```

## Что переезжает из пилота и как меняется

| Пилот | SkelCAD | Изменение |
|---|---|---|
| `domain/model.py` (Bracket) | `core/model.py` (Project → Requirements, Skeleton, Units → Parts/Joints) | схема общая, не кронштейна; ось → интерфейс скелета; `at_wall` → теги |
| `domain/findings.py` | `core/findings.py` | без изменений, `source` — имя плагина |
| `domain/builder.py` | `examples/bracket/generators/bracket.py` | генератор топологий — плагин проекта |
| `catalog/*.yaml` | `packages/std-gost/.../data/*.yaml` | в ядре таблиц нет; контракт таблиц описан в `context` |
| `rules/rules.py` | ГОСТ-правила → `std-gost`; правила кронштейна → `examples/bracket/plugins` | разделение по принадлежности |
| `checks/geometric.py` | общие (пересечения, контакт) → `rules/geometric.py`; ось, ключ → плагины примера | |
| `calc/estimates.py` | `examples/bracket/plugins/calc.py` | формат `CalcItem` — в ядре |
| `geometry/`, `export/`, `views/` | `geom/` | каталог через контекст, а не глобальный модуль |
| `pilot/pipeline.py`, `__main__.py` | `pipeline.py`, `cli.py` | сводка общая + метрики проекта |

Известные хвосты после шага 5: в `compare.html` 3D-сцена рисует полупрозрачную «стену» в плоскости Y=0
(наследие пилота; должна строиться по интерфейсу `mount_plane` скелета); SVG-виды берут направления
взгляда из глобальных осей, а не из скелета; сообщения правил только по-русски.

## Сознательно не делаем в M0

- Песочница исполнения генераторов, предложения (proposals), решения (decisions) — M1.
- Mates/кинематика: детали несут абсолютное положение; сопряжения — после первого адаптера.
- Мультиязычность текстов модели: поле `name` принимает строку или словарь `{ru:…, en:…}`,
  но правила пока выдают сообщения по-русски (D1, смысл 1 — открыт).

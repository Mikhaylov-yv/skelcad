## Цель и критерий готовности

Экран «Агент» показывал ход задачи как журнал разработчика: `вызов files_read {"path": …}`, ответы инструментов
JSON-обрезками по 500 знаков, трассировки ошибок, реплики модели с markdown-разметкой как есть, отчёт в конце того
же журнала. На задачу «Специальный болт» это 84 блока и семь экранов прокрутки. Остальные экраны пестрили: пять
цветов на одной странице (синий ссылок, фиолетовый агента, красный, оранжевый, зелёный), красные кнопки «Откатить»
на каждой карточке ленты, цветные полосы слева у коммитов, строка чисел с подписями капителью в каждой строке
варианта.

Критерий готовности:

1. Конструктор читает ход задачи как рассказ: «Читаю проект», «Правлю project.yaml: «компоновка болта»» →
   «коммит 47af0c3», «Собираю вариант A_base» → «AssertionError», и видит картинку, на которую смотрел агент.
   Сырые аргументы и ответы — только по кнопке «Подробности».
2. Отчёт агента — первым, оформленным (заголовки, списки, жирное), с итогом: сколько коммитов, ссылка в ленту,
   «компоновка ждёт вашего согласования» со ссылкой, если агент правил `project.yaml`.
3. Одна акцентная палитра: цвет означает «нужно решение» (ошибки — красный, ждёт решения — янтарный), всё остальное
   нейтральное. Главное действие экрана — одна залитая кнопка.
4. Ничего не потеряно: прежние данные (токены, стоимость, модель, шаги, аргументы, трассировки) доступны, но не
   на первом плане.

## Образец: «Ход обработки» в doc_ocr

Что берём из `~/dew/fesco/doc_ocr` (`src/doc_ocr/web/static/live.js`, `docs/ui/principles.md`):

| Приём в doc_ocr | Как применено в SkelCAD |
|---|---|
| События сервера переводятся во фразы от первого лица: «Читаю название и номер документа: стр. 3» | словарь `web/src/ui/agentSteps.ts`: вызов инструмента + аргументы → фраза («Смотрю компоновку p/A, вид «Сверху»»), ответ → итог одной строкой (сводка `summary`, «коммит …», ошибка без служебных префиксов) |
| Строка «что сейчас происходит» в шапке | `work__now`: у живой задачи — текущий шаг и сколько он идёт, у завершённой — «Готово за 3 мин 23 с» |
| Сцена: страница, на которую смотрит модель | агент сохраняет картинки из инструментов (компоновка, вид, вложение) файлами в папку задачи, рабочее место показывает их под шагом (`tool_result.images`, `GET /api/tasks/{id}/files/{name}`) |
| «Выводы» — короткий журнал решений | реплики модели — отдельные строки-заметки, длинные свёрнуты до первой фразы (`<details>`) |
| Служебные данные свёрнуты, пока их не спросили | «Подробности» раскрывает аргументы и ответы как есть |
| «Агент — коллега, а не режим»: объясняет себя словами регламента | отчёт агента первым, из markdown, с итогом «2 коммита · смотреть в ленте · компоновка ждёт вашего согласования» |
| Палитра: один фирменный синий, подкрашенные плашки, слова вместо значков | токены `--accent-soft`, `--warning-soft`, `--error-soft`; плашки с мягкой заливкой; значки только рядом со словами |

Не берём: проигрывание записанного хода с паузами (у SkelCAD шаги длинные, 3–40 с, и их мало; живая задача и так
идёт в своём темпе) и сцену на весь экран (у нас ход — панель рядом с задачей).

## Решения этапа (приняты 2026-10-21)

**D30. Ход работы агента показывается словами конструктора, не вызовами инструментов.** Событие задачи — факт для
журнала; что показать конструктору, решает рабочее место по словарю инструментов. Сырые данные остаются в
событиях и доступны по кнопке. Агент пишет в события то, что помогает рассказу: номер шага и время ответа модели
(`step`), картинки, которые он получил (`tool_result.images` — файлы в папке задачи). Отвергнуто: заставлять модель
писать «человеческие» пояснения к каждому шагу (лишние токены, ненадёжно); показывать только отчёт без хода
(конструктор теряет контроль над тем, что агент делал с моделью).

**D31. Одна акцентная палитра; цвет — это «нужно решение».** Акцент (синий) — ссылки, выбранное, главная кнопка,
состояние «у агента» и «выполняется». Красный — только ошибки (счётчики, сообщения). Янтарный — «ждёт вашего
решения» (непросмотренные изменения, компоновка не согласована или изменена после согласования, предупреждения).
Зелёный — только точка «выполнена» и «просмотрено». Всё остальное — нейтральное: автор-агент не фиолетовый,
коммиты без цветных полос, «Откатить» — обычная кнопка (красная — только «Откатить» в диалоге подтверждения),
«ок»-плашки без зелёного. Отвергнуто: цветовая кодировка автора (агент / человек) — слово «агент» в подписи уже
есть; отдельный цвет для каждого состояния задачи.

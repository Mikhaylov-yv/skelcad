# План этапа M2.6: специальный болт — тело вращения, разрез по оси, агент в рамках проекта

Статус: **предложен 2026-10-22**, ждёт решения конструктора (вопросы в конце). Предыдущий этап —
[10-m2-5-workbench-plan.md](10-m2-5-workbench-plan.md) (закрыт 2026-10-21). PMI и виды (бывший M2.6) сдвигаются
в M2.7: разрез по оси, который нужен болту, — первый «вид как объект» из той темы.

## Повод

Конструктор четыре раза пробовал сделать болт на `skelcad.br` и ни разу не получил деталь:

| Задание конструктора | Что вышло |
|---|---|
| «Нужен специальный болт, который стягивает элементы толщиной 150 мм, с посадочной поверхностью в центре 12 мм» | компоновка — серый квадрат; детали нет |
| «Сделай обычный болт М16, он должен стягивать изделия. Расстояние между плоскостями 100 мм» | компоновка согласована; «детали» — лимит 60 шагов, затем два таймаута |
| «Почему такая странная компоновка? Нужна в виде разреза по оси вращения, с понятными размерами и гайкой» | таймаут провайдера, ответа нет |
| «Давай сделаем болт с гайкой» + фото таблицы DIN 933 | лимит 60 шагов, два мусорных проекта в галерее |

Слова конструктора: «даже болт не могу нормально сделать»; «я хотел сделать специфический болт, а не получил
ничего»; «такой глубокий обмен данными между проектами не нужен без явного вызова».

Разбор (память `skelcad-bolt-analysis`, 2026-10-22) дал три причины, по весу:

1. **Ядро не умеет болт как деталь.** `Part = PlatePart | TubePart`; болт есть только как крепёж из каталога
   (`Fastener`: стержень + шайба + гайка, без головки) в отверстии листовой детали. Тела вращения с головкой,
   посадочной шейкой и резьбой описать нечем — этап «детали» для болта невыполним любой моделью, а компоновка
   болта (пакет 60×60 с осью) ничего не говорит конструктору, потому что болт до генератора не существует.
2. **Агент работал не на той модели и вслепую.** `deepseek-v4-flash` через OpenRouter не принимает картинки;
   LiteLLM молча уводит запрос на `glm-5.3-flash` (из 166 запросов deepseek ответил на 37, glm на 129; задача с
   фото — 60 из 60 на glm). glm отвечает до 189 с при таймауте клиента 180 с без повтора — оба `ReadTimeout`;
   glm хуже с инструментами (`files` строкой со сломанным JSON, 37 подряд `project_create`, пустые ответы).
3. **Агент не знает формат проекта и ядра и учится по чужим проектам.** В подсказке нет схемы; он читает
   генераторы других проектов (обрезаются на 6000 знаках), создаёт «справочные» проекты (`fmt_plate_ref`,
   `ref_bracket`), пишет файлы по неверным путям (`bolt_m10/project.yaml`), зовёт `model_query` без варианта
   (трассировка pydantic), повторяет один и тот же неудачный вызов десятки раз.

## Сквозной сценарий: специальный болт

1. «Новый проект» → основа «Болт с гайкой» (новый шаблон) или пустой. Задание первым сообщением: «Нужен
   специальный болт M10: стягивает пакет 150 мм, посадочная поверхность Ø12 h7 в середине пакета; гайка, шайба».
2. Агент (без чужих проектов) описывает требования и скелет: ось, опорная плоскость головки, плоскость гайки на
   150 мм, посадочное место Ø12 H7 длиной 12 в середине, пакет как обстановка (три элемента с отверстием),
   нагрузка `Fa`, если названа. `render(layout=true)` — **разрез по оси**: пакет штриховкой, отверстие, зона
   посадки, размеры 150 и Ø12, ось.
3. Конструктор поправляет числа на эскизе или словами, «Согласовать компоновку». Агент сам берётся за детали.
4. Генератор шаблона строит деталь-тело вращения: шестигранная головка s×k по ГОСТ 7798, гладкая часть Ø10,
   посадочная шейка Ø12 h7, резьба M10 длиной по гайке (+ 2–3 шага запаса), фаска; гайка и шайба — из каталога
   как покупные. Проверки: резьба выходит за гайку, посадка внутри отверстия, запасы K по `As` и по срезу шейки.
5. Конструкция: 3D, эскиз с размерами **разрезом по оси** (Ø с полем допуска, M10-6g, длины цепочкой, головка
   s/k, фаска 1×45°, выноска гайки и шайбы), вид с торца — шестигранник. Варианты (M10 / M12, длина посадки),
   «Выбрать», комплект: STEP, эскизы, отчёт.

## Решения (предложены, D33–D35 в `02-decisions.md`)

### D33. Агент работает в рамках своего проекта; другие проекты — только по явному указанию

Слова конструктора: «такой глубокий обмен данными между проектами не нужен без явного вызова».

- Задаче при создании сервер приписывает **область**: писать — только в свой проект; читать — свой проект,
  изделие-родитель (зоны и интерфейсы узла) и свои узлы. Агент (`agent.py`, обёртка `ScopedBridge`) не отдаёт
  модели `project_list` и `project_create` (узлы заводит конструктор кнопкой «+ Узел»), а у остальных
  инструментов проверяет `project` до вызова сервера: чужой проект → ответ «проект «bracket» вне задачи; работай
  в «bolt_m10»; чтобы агент смотрел другой проект, назовите его в сообщении» без обращения к серверу; `search`,
  `where_used`, `links` получают `project=<свой>` принудительно. Попытка попадает в ход работы: «Хотел читать
  проект bracket — вне задачи».
- **Явный вызов** — конструктор называет проект в сообщении кодом (`bracket`) или названием («Кронштейн»),
  можно `@bracket`. Сервер находит упоминания при создании задачи (`task.scope.refs`), названные проекты
  становятся читаемыми (не записываемыми); в поле сообщения под текстом появляется плашка «Агент сможет читать
  проект «Кронштейн»» с крестиком.
- Вместо чужих проектов агент учится у системы: инструмент **`reference(topic)`** отдаёт справку из пакета:
  `model` (виды деталей и их поля — из схемы ядра, с пояснениями), `generator` (сигнатура `generate(project,
  params, ctx) -> GenResult` и минимальный генератор), `variants`, `plugins`, `skeleton` (поля обстановки и
  интерфейсов), `template:<имя>` (файлы шаблона — копировать, не выдумывать). Подсказка агента и
  `INSTRUCTIONS` MCP говорят: «формат — через reference; чужие проекты — только если конструктор назвал».
- Внешний агент конструктора (Claude Code по токену) не ограничивается: это и есть явный вызов.
- Отвергнуто: права на уровне проектов в сервере (появятся с учётными записями); «память» агента по всем
  проектам по умолчанию (конструктор против).

### D34. Тело вращения — вид детали; болт — деталь, а не только крепёж из каталога

- Новый вид детали **`turned`** (`TurnedPart`): ось (`axis: {origin, direction}`, начало — опорный торец
  головки), **головка** `head: {shape: hex | cylinder | none, s, k, chamfer}` (шестигранник по ГОСТ 7798 / ISO
  4017, цилиндр d×k) и **профиль** — ступени вдоль оси от головки: `{id, length, diameter, feature: plain | fit
  | thread | neck, thread: M10, tolerance: h7, chamfer, fillet}`. Резьба — косметическая: тело по номинальному
  диаметру, на эскизе обозначение (`M10-6g`) и длина; поперечные отверстия и шлицы — позже (M2.7, вместе с PMI).
  Геометрия: половина профиля вращением вокруг оси (`revolve`), головка — призма шестигранника с конусной фаской
  30° по кромке, фаски и переходы — в профиле. Масса — из тела, как у остальных.
- **Гайка и шайба на детали**: `Fastener.fastener_type` получает `nut` — шайба и гайка из каталога на резьбовой
  ступени детали `part`, плоскость прижима на `clamp_depth` по оси детали (стержень не рисуется). Размер — из
  ступени `thread`.
- **Скелет тела вращения**: база `axis`, плоскости прижима, интерфейс `clamp` (`params: {thickness, hole}`,
  `loads: {Fa}`), интерфейс `seat` с телом-цилиндром (отверстие под посадку: диаметр, поле допуска `H7`);
  стягиваемый пакет — обстановка (`box` на элемент).
- **Разрез по оси** — новый вид `section` для компоновки и эскиза: плоскость через базу-ось и ось глубины вида;
  обстановка и листовые/трубные детали в плоскости — сечения со штриховкой (из OCCT `section`), отверстия и
  посадочные тела интерфейсов — просветы; детали ролей `bolt | screw | stud | pin` и покупной крепёж по ГОСТ
  2.305 не рассекаются — рисуются очерком. Размеры тела вращения: диаметры `Ø12 h7` с выноской, резьба
  `M10-6g`, длины ступеней цепочкой и общая длина, головка `s`/`k`, фаски `1×45°`; на виде с торца —
  шестигранник. Раздел `sketch` проекта: `views: [section, end]`, `section: {through: datum:axis}`.
- **Таблицы пакета `gost`**: `fasteners` дополняется M10 (ГОСТ 5915 / 11371) и размерами головки болта
  `head_s`, `head_k` (ГОСТ 7798-70 / ISO 4017); `fits` — интервалами (св. 10 до 18, 18–30, 30–50) для `H7`,
  `h7`, `k6`, `n6` по ГОСТ 25347. Числа сверить по таблицам при реализации, источник — в комментарии файла.
- **Шаблон «Болт с гайкой»** (`examples/bolt`, в «Новый проект» → основа): `project.yaml` (требования, скелет
  с осью и посадкой, пакет 150 мм обстановкой), `generators/bolt.py` (параметры: резьба, диаметр и длина посадки,
  положение посадки, класс прочности; вывод: длины ступеней, общая длина, гайка и шайба, `derived` с длиной
  резьбы и запасами), варианты A (M10, посадка Ø12×12 в середине), B (M12), `plugins/bolt_rules.py` (резьба
  выходит за гайку на ≥ 2 шага и не заходит в посадку; посадочная ступень внутри отверстия `seat`; `K_tension =
  As·Rp0,2 / Fa`, `K_shear` по площади шейки; гладкая часть ≤ посадки), `assumptions` (класс прочности,
  стопорение не требуется). Агент в проекте из шаблона меняет параметры, а не пишет генератор.
- Отвергнуто: болт только как крепёж в соединении двух пластин с добавленной головкой (быстро, но «специальный
  болт» — деталь со своим профилем, и в такой модели его нет); универсальный профиль произвольной формы
  (сплайны) — не нужен для болтов, валов и осей, усложняет размеры.

### D35. Картинки — только моделям со зрением; агент не падает на таймауте и не упирается в лимит молча

- У модели провайдера появляется признак **`vision`** (экран «Подключение агента»: LiteLLM — `GET /model/info`
  → `supports_vision`, OpenRouter — `/models` → `input_modalities`, иначе переключатель). Текстовой модели агент
  картинки не шлёт (так LiteLLM не уводит запрос на другую модель): если у провайдера указана **модель для
  картинок** (например `vision-fast-local`), агент просит её описать картинку («что изображено, подписи, числа»)
  и передаёт текст; иначе — текст «картинка недоступна этой модели» и плашка в поле сообщения при вложении
  картинки к такой модели.
- **Таймаут и повтор**: клиент провайдера ждёт до 600 с (у шлюза LiteLLM `request_timeout` 180 с — поднять
  для алиасов SkelCAD) и повторяет запрос один раз после `ReadTimeout` / 5xx; второй отказ — задача «провайдер
  не ответил» с отчётом по уже сделанному.
- **Лимит шагов**: за 10 шагов до конца агент получает «осталось 10 шагов — заверши и напиши отчёт»; на лимите —
  последний запрос без инструментов за отчётом, чтобы конструктор не остался без ответа.
- **Повторы и аргументы**: один и тот же вызов с ошибкой трижды подряд → подсказка «измени подход или спроси
  конструктора», пять раз → остановка с отчётом; `files` строкой JSON — разобрать; `files_read` постранично
  (`offset`, `limit`), ответ до 20 000 знаков, остальное — указанием «ещё N строк»; `model_query` без варианта —
  первый вариант проекта; ошибки инструментов — с подсказкой правильного вызова (валидация pydantic — какой
  параметр и пример).
- **Модель по умолчанию**: `deepseek-v4-flash` остаётся (справилась с заданием болта за 14 шагов, дёшева), но
  без картинок; на той же задаче прогнать `code-smart-api`, `chat-fast-api`, `glm-5.3-flash` — таблица шагов,
  времени, стоимости и результата в ревью, умолчание выбрать по ней (у алиасов Cerebras лимит 20 запросов в
  минуту и дневные капы — для умолчания рискованно).
- Отвергнуто: отключить fallback в шлюзе целиком (он нужен другим сервисам хоста); слать картинки всем и
  надеяться на fallback (это и есть сегодняшняя поломка).

| 5 | Страховки агента (D35): признак `vision` и его определение на экране провайдеров, описание картинок через модель для картинок, таймаут 600 с с повтором, предупреждение за 10 шагов и отчёт на лимите, защита от повторов, `files` строкой, `files_read` постранично, `model_query` без варианта, подсказки в ошибках; прогон моделей на задании болта | 1 день |

Итого 4–5 дней. Порядок: 4 и 5 можно делать параллельно с 1–3; на `skelcad.br` выкладывать по мере готовности
(4 и 5 — сразу, они не ломают текущие проекты).

## Вопросы конструктору (с допущениями, если ответа нет)

1. «Посадочная поверхность в центре 12 мм» — это Ø12 h7 в середине пакета, длиной в средний элемент? Допущение:
   Ø12 h7, длина 12 — оба параметры варианта.
2. Класс прочности и материал болта — 8.8 (сталь 35, 40Х)? Допущение: 8.8, `Rp0,2` 640 МПа в таблице материалов.
3. Гайка ГОСТ 5915 (DIN 934) и шайба ГОСТ 11371 без стопорения? Допущение: да; стопорение — замечанием.
4. Компоновка тела вращения всегда разрезом по оси (вместо главного вида)? Допущение: да, главный вид остаётся
   в `sketch.views` по желанию.
5. Модель по умолчанию — оставить `deepseek-v4-flash` без картинок, описание картинок через `vision-fast-local`?
   Допущение: да, до результата прогона моделей.

Мусор от задач: проекты `fmt_plate_ref`, `ref_bracket` и файл `bolt_m10/project.yaml` — убрать в корзину по
слову конструктора (сервер сам не трогает проекты).

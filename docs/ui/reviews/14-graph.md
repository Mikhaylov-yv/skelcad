# Ревью: поиск по всем проектам и блок «Связи» (шаг 4 M2.2)

Дата: 2026-10-20. Экраны: «Проекты» (`/?q=…`) — поиск по сущностям всех проектов по индексу связей в Postgres;
«Вариант» — блок «Связи» в правой панели у выделенной детали (3D, эскиз), размера, ссылки замечания или сущности
компоновки: что она содержит, к чему привязана, кто на неё ссылается, с переходом по связи; «Где используется»
для материала, позиции каталога, базы, интерфейса, обстановки — по всем проектам. Скриншоты:
`14-projects-search.png` (поиск «wall»: базы, интерфейсы, обстановка, расчёты, швы, замечания трёх проектов),
`14-variant-links-layout.png` (компоновка, выделена база `datum:wall`: размер, проект, интерфейс, которые на неё
ссылаются), `14-variant-links-part.png` (3D, плита: отверстия, материал, размеры и замечания к ней),
`14-where-used.png` (материал St3sp: детали трёх вариантов и других проектов). Чеклист — `docs/ui/checklist.md`.

1. Видимость состояния — ок: «найдено: N», «список обрезан» при лимите, «Ищу…» и «Загружаю связи…» на время запроса; если граф не настроен, экран говорит это словами, а не падает (503 → подсказка про `SKELCAD_DATABASE_URL`).
2. Соответствие реальному миру — ок: виды сущностей и типы связей названы по-русски словами конструктора (база, интерфейс, обстановка, деталь, отверстие, крепёж, материал, позиция каталога; «привязан к базе», «крепится к интерфейсу», «замечание к»); ссылки в той же грамматике, что в замечаниях и на эскизах.
3. Свобода и контроль — ок: запрос живёт в адресе (`?q=`), назад и вперёд работают; клик по связи переводит выделение, обратно — клик по дереву или «Снять выделение»; «Где используется» раскрывается по кнопке, не грузится само.
4. Единообразие — ок: те же ссылки `kind:id` в «Связях», в замечаниях, у агента (`links`, `search`, `where_used`) и в адресах (`?part=`, `?ref=`); блок «Связи» одинаков в 3D, эскизе и компоновке.
5. Предотвращение ошибок — ок: запрос короче двух знаков не отправляется (ответ сервера словами); индекс обновляется после каждого коммита и сборки, устаревшие варианты снимаются; ответ не той формы показывается как ошибка.
6. Распознавание — ок: у каждой связи имя сущности и вид; у результата поиска — проект и вариант; ссылка ведёт именно к сущности (деталь — в 3D с выделением, база — в компоновку с выделением на эскизе).
7. Гибкость — ок: глубокие ссылки `/?q=wall`, `/p/<p>/<v>?mode=layout&ref=datum:wall`; те же запросы агенту через MCP и по REST (`/api/graph/*`); `hops`, `kinds`, `direction` в API.
8. Минимализм — проблема → смягчено: при многих проектах поиск даёт длинный список (32 строки на «wall» при трёх клонах кронштейна); в строке есть проект и вид, но группировки по проектам нет — хвост (группировать по проекту, фильтр по виду в форме).
9. Исправление ошибок — ок: ошибка запроса показывается в панели с текстом сервера; граф выключен — одна строка с причиной, остальное рабочее место работает.
10. Помощь — ок: подсказка у поля поиска («id, имя, роль, примечание…»), руководство конструктора (шаг 7), памятка агенту (`links` дешевле `files_read`).

Хвосты: группировка результатов поиска по проектам и фильтр по виду; «Связи» на 2 шага в интерфейсе (API умеет,
экран показывает соседей); «где используется» для стандартов и нагрузок без кнопки (сейчас — у материала, каталога,
базы, интерфейса, обстановки, зоны, нагрузки).

# Ревью: создание проекта из рабочего места

Дата: 2026-10-21. Экран: «Проекты» (`/`), кнопка «Новый проект» в шапке → форма-карточка: название изделия,
код проекта (подставляется из названия транслитерацией — «Опора насоса на раме Ø108» → `opora_nasosa_na_rame_108`,
можно поправить), основа — «пустой проект — скелет опишет агент по задаче и наброску» или «копия примера «…» (id)»
по шаблонам сервера, «Создать» / «Отмена». Проект создаётся коммитом конструктора (`POST /api/projects`), после
создания открывается экран «Агент» этого проекта; у пустого проекта (без вариантов) на экране «Агент» подсказка
«Проект пока пустой: … приложите набросок … агент заполнит требования, скелет и обстановку и покажет компоновку».
У MCP-инструмента `project_create` появился `title`. Скриншоты: `19-project-new.png`, `19-project-agent-empty.png`,
`19-projects-created.png`. Чеклист — `docs/ui/checklist.md`.

1. Видимость состояния — ок: «Создаю…» на кнопке, форма закрыта на время запроса; новый проект сразу в списке с
   меткой «у конструктора» и коммитом «Проект … «название» [из шаблона …]» от имени конструктора.
2. Соответствие реальному миру — ок: «название изделия», «основа», «копия примера» вместо «template»; код проекта
   объяснён как имя папки и ссылок.
3. Свобода и контроль — ок: «Отмена» без последствий; код можно переписать руками (после этого из названия не
   подставляется); проект — обычный git-репозиторий, лишний удаляет администратор на сервере (кнопки удаления в
   интерфейсе нет намеренно: история изделия не стирается одним кликом).
4. Единообразие — ок: та же форма-карточка, что у провайдеров и токенов; те же слова «Создать», «Отмена»; тот же
   инструмент у агента (`project_create`, теперь с `title`).
5. Предотвращение ошибок — ок: код проверяется на лету по правилу сервера (строчные латинские, цифры, «-», «_», до
   64 знаков) — поле подсвечено, «Создать» закрыта; повтор имени и неизвестный шаблон приходят словами и форма
   остаётся заполненной.
6. Распознавание — ок: основа выбирается из списка с названиями примеров, не вводится код шаблона; код
   подставляется сам.
7. Гибкость — ок: Tab по полям, Enter отправляет; то же через MCP (`project_create`) и REST (`POST /api/projects`).
8. Минимализм — ок: одна кнопка в шапке, форма по требованию, три поля.
9. Исправление ошибок — ок: «проект «planka_kopiya» уже есть» под формой, значения на месте.
10. Помощь — ок: подсказка формы объясняет, что такое проект и что будет дальше; пустое состояние списка ведёт к
    кнопке; у пустого проекта на «Агенте» подсказка, что приложить и написать.

Проверка живьём (dev-сервер, Playwright `web/node_modules/.scratch/check-project-create.mjs`): код из названия
`opora_nasosa_na_rame_108`; четыре основы (пустой + bracket, pipe_support, plate с названиями); пустой проект →
`/p/opora_nasosa_na_rame_108/agent`, заголовок «Опора насоса на раме Ø108 · Задача агенту», подсказка пустого
проекта; копия plate → проект `planka_kopiya` с вариантами A_base и B_wide, карточка в списке, коммит
«Проект planka_kopiya из шаблона plate»; повтор имени — ошибка словами, форма остаётся; ошибок страницы нет.

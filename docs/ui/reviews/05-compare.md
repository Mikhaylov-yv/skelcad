# Ревью: экран «Сравнение» (шаг 5 M2)

Дата: 2026-10-19. Экран: `/p/<project>/compare` — таблица метрик по вариантам (лучший
выделен), 3D каждого варианта бок о бок с общими видами, переход к варианту. Скриншот:
`05-compare.png`. Чеклист — `docs/ui/checklist.md`.

1. Видимость состояния — ок: пока несобранные варианты собираются, видно «Сравниваю варианты… до 180 с на каждый» (aria-live).
2. Соответствие реальному миру — ок: метрики те же, что в `compare.html` и у инструмента `compare` («Масса изготавливаемых деталей, кг», «Заготовки», «Длина швов, мм», «Минимальный запас K», «Число анкеров»); единицы в заголовках строк.
3. Свобода и контроль — ок: экран только для чтения, переход к варианту по заголовку столбца.
4. Единообразие — ок: виды те же четыре кнопки, подписи моделей — та же строка «масса · K min», лучший выделен одинаково с `compare.html` (жирный, зелёный).
5. Предотвращение ошибок — ок: при одном варианте экран объясняет, что сравнивать не с чем; ссылка «Сравнение» на карточке проекта показывается только при двух и более вариантах.
6. Распознавание — ок: столбцы подписаны id и названием варианта; лучший помечен всплывающей подсказкой и скрытым текстом для читалок.
7. Гибкость — ок: тот же результат доступен агенту через `compare` и в CLI; 3D до трёх моделей в ряд, дальше — перенос.
8. Минимализм — ок: таблица и ряд моделей, без лишних элементов.
9. Исправление ошибок — ок: ошибка сборки одного из вариантов показывается текстом сервера и кнопкой «Повторить».
10. Помощь — ок частично: смысл «лучший» виден по выделению; описание метрик — в отчёте варианта; руководство конструктора — шаг 9.

Пороги: таблица и ряд 3D на 1366×768 — таблица целиком, модели после одной прокрутки (`05-compare.png`); три модели по 300 кБ грузятся ~1 с на LAN.

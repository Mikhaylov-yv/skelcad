# Ревью: вложения к задаче агенту (M2.3 шаг 1, D28)

Дата: 2026-10-21. Экран: `/p/<project>/agent` — блок «Вложения» под текстом задачи: «Добавить файл»
(несколько файлов), вставка картинки из буфера в текст задачи, список файлов проекта с миниатюрами,
отметка «к задаче» (новый файл отмечен сразу), «Показать», удаление; в ходе задачи — «Вложения задачи»
и строки «вложение … передано модели как изображение», «изображение из инструмента передано модели».
Файл сохраняется в `attachments/` репозитория проекта коммитом конструктора. Скриншот:
`15-agent-attachment.png`. Чеклист — `docs/ui/checklist.md`.

1. Видимость состояния — ок: «Загружаю…» на кнопке, «вложений: N» у «Запустить», в ходе задачи видно,
   какие вложения ушли модели и как (изображением или текстом); ошибка загрузки — красной строкой.
2. Соответствие реальному миру — ок: «набросок от руки, фото, экспорт из доски», размер в px и КБ, автор;
   файл переименовывается в латиницу с датой и временем, но исходное имя узнаваемо (`eskiz`, `nabrosok`).
3. Свобода и контроль — ок: вложение можно снять с задачи галочкой, удалить (подтверждение; это коммит, откат в
   ленте), посмотреть в новой вкладке; загрузка закрыта, пока проект у агента.
4. Единообразие — ок: тот же список-карточки и бейджи, что у задач; ссылка «Показать» как у замечаний.
5. Предотвращение ошибок — ок: допустимые типы и предел размера в подсказке и в `accept` диалога; сервер
   отвергает чужие типы, пустые и битые файлы, слишком большие (16 МБ) словами; растр уменьшается сам;
   пути вложений в задаче проверяются при постановке.
6. Распознавание — ок: миниатюра и имя файла рядом с галочкой; у задачи в истории — «вложений: N».
7. Гибкость — ок: вставка из буфера (скриншот, кусок чертежа), несколько файлов за раз; агент в терминале
   получает то же через `attachment`; API `/api/projects/{p}/attachments`.
8. Минимализм — ок: блок свёрнут в один ряд, пока вложений нет; подсказка в две строки.
9. Исправление ошибок — ок: ошибка сервера показывается текстом под формой, загрузка повторяется.
10. Помощь — ок: подсказка объясняет, где хранится файл и что агент с ним сделает.

Проверка живьём: dev-сервер, загрузка наброска кронштейна (1400×1000) через диалог — коммит
`constructor: вложение 20261021-0707-sketch-bracket.png (изображение 1400×1000)`, миниатюра, отметка к задаче;
задача с вложением — в ходе задачи «вложение … передано модели как изображение». Проверка самой модели на
cloud ждёт секрета `SKELCAD_LLM_API_KEY` (пуст с M2).

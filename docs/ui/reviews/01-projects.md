# Ревью: экран «Проекты» (шаг 1 M2)

Дата: 2026-10-19. Экран: список проектов на сервере, карточка проекта с вариантами и числами
последней сборки. Чеклист — `docs/ui/checklist.md`.

1. Видимость состояния — ок: у каждого проекта метка «у конструктора / у агента», у варианта «собрано N мин назад» или «не собран»; при загрузке «Загружаю проекты…» (aria-live).
2. Соответствие реальному миру — ок: «масса, кг», «K min», «ошибок / предупреждений», «Последнее изменение: агент (claude-code) · 5 мин назад · анкеры M20…». Нет слов «коммит», «hash», «репозиторий».
3. Свобода и контроль — ок (экран только для чтения; «Повторить» при ошибке).
4. Единообразие — ок: та же строка чисел `NumbersRow`, что пойдёт на экраны варианта, ленты и сравнения; цвета уровней — общие токены.
5. Предотвращение ошибок — ок (действий, меняющих модель, на экране нет).
6. Распознавание — проблема: вариант не кликается, пока нет экрана «Вариант» → по плану ссылка появится в шаге 3; до тех пор карточка не обещает перехода (нет подчёркиваний и стрелок).
7. Гибкость — ок частично: клавиатурная навигация по ссылкам шапки; глубокие ссылки появятся с шагом 3.
8. Минимализм — ок: карточка = название, стандарты, таблица вариантов с числами, одна строка про последнее изменение; hash коммита — только во всплывающей подсказке.
9. Исправление ошибок — ок: ошибка сервера показывается словами из `{error}` (role=alert) и кнопкой «Повторить»; 401 превращается в «нужен вход».
10. Помощь — ок: пустое состояние объясняет, откуда берутся проекты (агент `project_create` или шаблон).

Пороги: первая отрисовка — статика 100 кБ gzip; контраст токенов текста ≥ 4.5:1 в обеих темах
(проверено по значениям `--text`/`--muted` на `--bg`/`--surface`).

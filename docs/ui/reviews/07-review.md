# Ревью: замечания агенту — пометки на модели (шаг 7 M2)

Дата: 2026-10-19. Экран: панель «Замечания агенту» на экране варианта — «Пометить на модели» →
клик по детали в 3D → деталь и точка (мм) → текст → `review.yaml` коммитом; список открытых и
закрытых с ответами агента; «Закрыть самому». Агент: `review_list`, `review_resolve` (MCP),
счётчик открытых в `project_read`. Скриншот: `07-review.png`. Чеклист — `docs/ui/checklist.md`.

1. Видимость состояния — ок: в режиме пометки — подсказка «Кликните по детали в 3D» и курсор-прицел; поставленная пометка — жёлтый шар на модели, закрытая — зелёный; открытые замечания видны агенту в первой строке `project_read`.
2. Соответствие реальному миру — ок: пометка на модели, как карандашом на распечатке: «пометка: cheek_L · точка −82, 122, 66 мм»; слова «замечание», «ответ», а не «issue».
3. Свобода и контроль — ок: пометку можно отменить до отправки; замечание можно закрыть самому; всё — коммиты, откатываемые в ленте.
4. Единообразие — ок: id R1, R2… как у допущений G1…; подсветка детали по клику на id, как у замечаний правил.
5. Предотвращение ошибок — ок: без текста не отправляется («Нужен текст замечания»); повторное закрытие невозможно (сервер отвечает «уже закрыто»).
6. Распознавание — ок: деталь и точка подставляются сами, конструктору не нужно знать id деталей.
7. Гибкость — ок: тот же файл агент читает через `review_list`, а конструктор может редактировать руками в своём клоне.
8. Минимализм — ок: одна кнопка, одно поле; список компактный.
9. Исправление ошибок — ок: ошибка сервера показывается под формой (`role=alert`), пометка остаётся, можно отправить снова.
10. Помощь — ок: пустое состояние объясняет, что делать и как агент это увидит; плейсхолдер даёт пример.

Пороги: пометка ставится за два клика; список и форма видны без прокрутки на 1366×768.

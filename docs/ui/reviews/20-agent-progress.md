# Ревью: ход работы агента словами (M2.4, D30)

Дата: 2026-10-21. Экран: «Агент» (`/p/<project>/agent`), заново. Повод — замечание конструктора после первой
задачи через LiteLLM («Специальный болт», DeepSeek V4 Flash, 17 шагов, 84 события): «текстовая огромная штука с
рассуждениями очень пугает». Было (`20-agent-before.png`): журнал `вызов files_read {"path": …}`, JSON-обрезки
ответов, трассировка сборки, реплики с `**` как есть, 6 900 px прокрутки. Стало: слева задача (текст, вложения
чипами, вариант / провайдер / модель, «Как это работает» свёрнуто) и список задач с точкой состояния; справа —
состояние («выполнена · Готово за 3 мин 23 с», строка модель · шаги · токены · стоимость · кто), отчёт агента
первым из markdown с итогом («2 коммита · смотреть в ленте · компоновка ждёт вашего согласования · открыть
компоновку»), затем «Что делал агент · шагов 27»: фразы по словарю инструментов, итог ответа одной строкой,
картинка, на которую смотрел агент, реплики модели заметками (длинные — до первой фразы, раскрываются), ошибка
инструмента словами без трассировки; «Подробности» раскрывает сырые аргументы и ответы. Скриншоты:
`20-agent-report.png`, `20-agent-steps.png`, `20-agent-images.png`, `20-agent-details.png`. Чеклист —
`docs/ui/checklist.md`.

1. Видимость состояния — ок: плашка состояния и строка «что сейчас» (у живой задачи — текущий шаг и сколько он
   идёт, крутящийся значок у висящего вызова, «Обдумываю следующий шаг…» между вызовами, список прокручивается к
   последнему шагу); у завершённой — «Готово за …», у упавшей — «Остановилась с ошибкой» и текст ошибки.
2. Соответствие реальному миру — ок: «Читаю проект», «Правлю project.yaml: «…»» → «коммит 47af0c3», «Смотрю
   компоновку …, вид «Изометрия»», «Собираю вариант …», «Проверяю правила», «Ищу в каталоге «болт»»; имена видов
   по ЕСКД; никаких `tool_call` / `args` на первом плане.
3. Свобода и контроль — ок: «Остановить» у живой задачи; «Подробности» включаются и выключаются; реплики
   раскрываются по одной; задача выбирается из списка, прежние задачи доступны.
4. Единообразие — ок: те же плашки состояния, что в ленте и на карточках; тот же markdown-рендер для отчёта и
   реплик; одна фраза на инструмент для обоих исполнителей (OpenAI-совместимый и Claude Code — имена инструментов
   совпадают); неизвестный инструмент показывается именем с аргументами, а не ломает список.
5. Предотвращение ошибок — ок: «Запустить» закрыта без текста и пока проект у агента (строка «Проект у агента —
   дождитесь конца задачи или остановите её»); файлы задачи отдаются только по безопасному имени
   (`img-001.png`), имена из событий, чужие пути — 400.
6. Распознавание вместо припоминания — ок: картинка компоновки под шагом (не надо открывать «Компоновку», чтобы
   понять, что видел агент), коммиты с хэшем и файлами прямо в шаге, ссылки в ленту и на компоновку из итога.
7. Гибкость — ок: длинные ответы обрезаны до строки, но целиком — в «Подробностях»; `aria-live` у состояния,
   `details/summary` для реплик (клавиатура); тот же `events.jsonl` остаётся для разработчика.
8. Минимализм — ок: 84 блока → 27 шагов и 5 заметок; подсказки формы свёрнуты в «Как это работает»; «Вложений пока
   нет» и список форматов убраны с первого плана; у задачи в списке — одна строка.
9. Исправление ошибок — ок: «Собираю вариант …» → «AssertionError» красным значком, трассировка — в
   «Подробностях»; ошибка задачи — плашкой под отчётом с текстом.
10. Помощь — ок: пустой проект — подсказка, что приложить и описать; «Как это работает» объясняет, что делает агент
    и как попадают вложения; у «Подробностей» подсказка «Аргументы вызовов и ответы инструментов как есть».

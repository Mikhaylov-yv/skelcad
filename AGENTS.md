# Как агенту работать со SkelCAD

Два разных случая: агент **конструирует** изделие через сервер SkelCAD (MCP) и агент
**разрабатывает** сам SkelCAD в этом репозитории.

## 1. Конструирование через MCP

Подключение (Claude Code): `claude mcp add --transport http skelcad https://skelcad.br/mcp
--header "Authorization: Bearer <токен>"`. Токен выдаёт администратор сервера; по токену сервер
узнаёт клиента и подписывает его коммиты (`SkelCAD agent (<клиент>)`).

**Принцип.** Модель изделия — источник истины: `project.yaml` (требования, скелет, пакеты
стандартов, параметры), `variants/*.yaml` (параметры топологий), `generators/*.py` (параметры →
узлы, детали, соединения), `plugins/*.py` (правила, проверки, расчёты, метрики). Геометрия,
чертежи и отчёты — производные. Агент предлагает и строит, конструктор решает: каждое изменение —
коммит под именем агента, конструктор смотрит историю и откатывает лишнее.

**Цикл работы.**

1. `project_list`, `project_read` — что за изделие, какие варианты, какие стандарты; `review_list` —
   открытые замечания конструктора (пометки на модели), на каждое нужен `review_resolve` с ответом.
2. `check` или `build` — текущее состояние: замечания (error / warning / info), запасы K, масса.
3. Заземлиться: `measure` (расстояния, зазоры, пересечения, массы, ЦТ), `context_search` /
   `context_lookup` (каталоги: крепёж, анкеры, материалы, трубы), `render` (посмотреть вид).
4. Изменить: `files_read` → правка → `files_write` с сообщением «что и зачем». Один вызов —
   одно логическое изменение, несколько файлов можно в одном вызове.
5. Проверить: `build` (или `check`), затем `diff` (`HEAD~1` → `HEAD`) — что именно изменилось в
   модели, геометрии, сводке и замечаниях.
6. Повторять 3–5. Тупиковый шаг — `revert` (новый коммит-откат, история не переписывается).
7. Итог — `compare` по вариантам и короткий отчёт конструктору: что сделано, какие коммиты,
   какие допущения приняты, какие замечания остались.

**Правила.**

- Замечания уровня `error` блокируют приёмку — не оставляй их; `warning` объясни или устрани.
- Числа бери из `measure` и каталогов, а не из головы. Единицы: мм, кН, кг, кН·м.
- Большие данные — срезами: `model_query` с `path` (`parts[id=…]`, `welds`, `skeleton.interfaces`).
- Не переписывай генератор целиком ради одного параметра: параметры живут в `variants/*.yaml`.
- Допущения, которые ты принял, запиши в `assumptions` варианта или проекта.
- Сообщение коммита — по-русски (или на языке проекта), по сути: «анкеры M20: K_anchor 1.14 → 1.62».

## 2. Разработка SkelCAD в этом репозитории

- Документы: `docs/architecture/01-vision-and-architecture.md` (замысел), `02-decisions.md`
  (журнал решений), `03-m0-plan.md`, `04-m1-plan.md`, `05-m2-plan.md` (планы этапов со статусом).
- Код: `src/skelcad/core` (модель), `geom` (OCCT), `rules` (плагины), `pipeline.py`, `server/`
  (FastAPI + MCP + git-проекты; `api.py`, `auth.py`, `params.py`, `review.py`, `tasks.py`, `tokens.py`),
  `worker.py` (изолированное исполнение кода проектов), `agent.py` (встроенный агент из workbench),
  `measure.py`, `render.py`, `diff.py`. Workbench — `web/` (Vite + React + TS, three.js). Пакет стандарта — `packages/std-gost`.
- Проверки перед коммитом: `uv run ruff check src tests && uv run ruff format src tests &&
  uv run pytest -q`. Код проектов (генераторы, плагины) исполняется только в воркере.
- Деплой: push в `main` на git.br → `.gitea/workflows/deploy.yml` → cloud (`~/srv/skelcad`,
  `docker compose`, nginx `skelcad.br`). Локально: `uv run skelcad serve` (без токенов — режим
  разработки) и `uv run skelcad worker --queue <папка>` или подпроцесс-воркер по умолчанию.
- Интерфейс (workbench, `web/`): проектируем по ISO 9241-110, каждое изменение экрана проверяем
  по чеклисту `docs/ui/checklist.md` и записываем ревью в `docs/ui/reviews/` (см. `05-m2-plan.md`).
- Тексты, сообщения правил и документация — по-русски; идентификаторы — по-английски.
